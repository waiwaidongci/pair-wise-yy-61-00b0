# pair-wise-yy-61 航空器定检工作包执行与放行审阅平台

支持工卡依赖、测量值容差校验、**断网继续执行与按来源合并**、分阶段签字、版本差异和放行锁定。超差项目必须由授权人员处理后才能继续。

## 机库断续网络下的合并模型

机库网络不稳定，执行人员断网后可继续填写工卡的**测量值、发现、证据说明**；网络恢复后与服务器正式记录合并。

- **不按后到覆盖**：每个执行字段保存三路信息（`baseValue` 上次同步值 / `serverValue` 正式记录值 / `localValue` 本地草稿值）与**字段来源**（server / local / both / conflict）。
  - 仅本地改 → 保留草稿并入发件箱推送；
  - 仅服务器改 → 以正式记录为准；
  - 双方改同字段且值不同 → 生成**字段冲突项**，由人工在同步中心选择"保留本地并推送"或"采用服务器值"，系统不自动覆盖。
- **按工卡版本判定**：离线期间工卡被修订（如 R6→R8），静态要求随服务器升级，有本地成果的工卡结论失效，必须核对新版本后重新确认；带旧版本基线的推送会被服务器拒绝。
- **授权 / 阶段签字 / 放行的失效规则**：离线期间发生
  - 超差被授权 → 该工卡本机完成结论失效、草稿保留，完成操作挂起，执行人复测后**重新确认**；
  - 某阶段在服务器被签署 → 本机离线签署标记**需重签**；
  - 工作包被锁定放行 → 所有待同步结论失效，正式记录只读，内容修改被服务器拒绝。
- **合并失败不丢数据**：推送返回 500/断网时，本地草稿、发件箱、冲突项原样保留，不写成功审计，可随时重试。
- **重试幂等**：每个发件箱操作带客户端 `opId`，服务器按 `opId` 去重；响应丢失后重放只回放结果、不重复落账。需要按新版本重试时会生成新 `opId` 并重定基线。审计记录按稳定键去重（`op:` / `event:` / `legacy:` 前缀），同一操作永远只有一条审计。
- **旧数据迁移**：旧版扁平 localStorage 数据自动迁移到带来源元数据的 v2 结构，旧测量值/发现、签署状态、审计记录全部保留可用；损坏数据安全回退到服务器快照。

## 同步中心（/sync）

- 查看本地发件箱、字段冲突、失效结论并逐项处理（保留本地/采用服务器、重新确认、重新签署、放弃草稿）；
- 内置服务器情景模拟：离线期间授权、阶段签字、锁定放行、工卡修订、他人并发同改一字段、下次推送 500，便于完整演练合并流程。

## 技术栈

React、Fluent UI、Redux Toolkit（含异步 thunk）、React Router、Vite、TypeScript。

核心模块位于 `src/sync/`：

| 文件 | 职责 |
| --- | --- |
| `types.ts` | 字段来源、发件箱、冲突项、失效项、审计等领域模型 |
| `server.ts` | 可推进的模拟正式记录服务器（快照、授权/签字/放行/修订、幂等推送） |
| `merge.ts` | 纯函数三路合并引擎：字段来源裁决、版本判定、失效生成 |
| `cards.ts` | 服务器工卡 ↔ 客户端工卡转换 |
| `migration.ts` | 旧版 localStorage 数据迁移到当前 schema |
| `../store.ts` | 发件箱、`runSync`（拉取→合并→推送→回流）、冲突/失效处理、幂等审计 |

## 运行

```bash
npm install
npm run dev      # http://localhost:62061
npm test         # 合并引擎 + store 集成场景（共 70 项断言）
npm run build
```

工卡草稿、发件箱、冲突/失效项与审计操作保存在 `localStorage`（键 `yy61-work-package`，带 `schemaVersion`）。
